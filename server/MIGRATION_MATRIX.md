# Frontend to Laravel migration matrix

The Next.js application still renders the public site, auth pages, user dashboard, and admin console. `LARAVEL_API_URL` sends API requests to Laravel through Next rewrites. Both servers share the original PostgreSQL tables and `qfs_session` cookie.

Admin, user and local demo login supported. |

## Existing frontend placeholders that need product content or rules

- See [IMPLEMENTATION_STATE.md](IMPLEMENTATION_STATE.md) for the current KYC scope and remaining operational gaps.
- Rewards and Pay Bills have no server rules, so their dashboard navigation entries are hidden until those features are implemented.
- Loan approval currently changes loan status and due date without disbursing money. A disbursement rule and repayment workflow are needed before representing approved loan funds as spendable.
- Card issuance and card-specific transaction processing depend on a card provider or an explicit local simulation policy. Freeze/unfreeze is wired for existing card records.
- The videos panel and legal/social footer links are hidden until actual content and URLs exist. Account access help and footer support use the published support email.
- The original document seed referenced PDF paths with no files in `public/`. The non-destructive Laravel seeder does not create broken document rows. Admins can now upload PDFs or add real document links.
